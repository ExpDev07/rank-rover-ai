## Responsibilities and contracts

- **Ownership and scoped routes:** `routes/web.php` keeps `auth` and `subscribed` gates and applies Laravel's `can:manage,app` authorization middleware and `scopeBindings()` to every `/app/{app:slug}` route (app show/update, content list/create/show/write/retry/tweak, cluster create). `AuthServiceProvider` maps `App` to `AppPolicy`; `AppPolicy::manage()` allows only `user_id` ownership and otherwise uses `denyAsNotFound()`. `App::childRouteBindingRelationshipName()` maps nested `content` to the actual `contents()` relationship, preventing same-owner and cross-account parent mismatches before controller work.
- **Query and association boundaries:** `ContentController::renderIndex()` groups queued/current-revision alternatives inside `$app->contents()` and resolves `show_cluster` through `$app->contentClusters()`. `CreateContentRequest` scopes optional `cluster_id` existence to the route app. `AppController` anchors app lists to the authenticated user and app-detail content to the selected app.
- **AI transport:** `app/Services/AiTransport.php`, method `request()`, is the shared OpenAI boundary. It preserves message order and `gpt-4-turbo-preview`, enables JSON mode when requested (generation/recommendations, not tweaks), checks the first message, repairs JSON with `Ahc\Json\Fixer`, and decodes objects distinctly from lists. Provider/repair failures become `AiResponseValidationException`, whose generic message is `Content generation failed. Please try again.` and which retains no private exception chain.
- **AI validation:** `AiContentService::article()` requires an object with nonblank string `content` and returns Markdown plus the conversation with the original assistant message appended. `recommendations()` validates the entire nonempty titles list and every nonblank title/keyword, then returns only `title` and `keywords`. It preserves accepted values and does not enforce exactly eight titles. Neither service logs private payloads.
- **Jobs:** `GenerateContentJob` and `TweakContentJob` resolve `AiContentService` during execution, rather than serializing services. They create and associate a new current revision, announce generating, persist validated output/conversation on success, and on handled failure save an errored revision with null article content, empty messages, and generic retry text. Both clear `content_queued` before the terminal notification. Tweaks append the instruction to source history and create a child without modifying earlier revisions. `ContentRevisionStatusChangedEvent` retains `{id, status}` on the private `contentRevisions.{id}` channel.
- **Recommendation persistence:** `ContentClusterController::handleCreate()` defaults omitted `only_target_audience` to false, obtains validated recommendations before opening the persistence transaction, and translates AI failures to the `generation` validation key. One `DB::transaction()` creates the app-owned cluster and all content with explicit request/relationship/state fields. A mid-save persistence exception rolls everything back; it is not converted by the AI-error catch. Successful redirect remains `/app/{slug}/content?show_cluster={id}`.
- **Dispatch:** `app/Actions/DispatchContent.php`, method `execute()`, is used by all four `ContentController` entry points: create/write/retry/tweak. It refreshes and snapshots the prior queue flag/current revision, transactionally saves queued=true and dissociates the current revision, then dispatches through `Illuminate\Contracts\Bus\Dispatcher` only after the outermost commit. Outer rollback cancels the callback. A pre-acceptance dispatch throw restores the captured fields without deleting revision history and raises a generic `generation` validation error. A newly created record remains unqueued with no revision for retry. There is no post-dispatch stale model save to overwrite synchronous terminal state.
- **Tweak guard:** `TweakContentRequest` requires a string `tweak`; global trimming/empty-string conversion makes blank input invalid. `ContentController::handleTweak()` additionally requires the *current* revision to be `ContentGenerationStatus::Generated` before dissociation/dispatch; generated historical revisions do not substitute. The UI's 20-character button threshold is a UI constraint, not the server's nonblank-string rule.
- **UI recovery:** `resources/js/components/app/content/CreateContentDialog.jsx` preserves state on errors, renders manual `generation` and AutoPilot recommendation errors in alert regions, clears errors before another attempt, and clears working flags in `onFinish`. `resources/js/pages/app/content/show.jsx` displays generation/tweak errors, preserves tweak input until success, and posts retries to `/app/{app.slug}/content/{content.slug}/retry`. Unqueued revisionless or errored content shows **Retry now**. Polling is limited to queued/idle/generating work, pauses during submissions, and uses an effect-owned 10-second timeout with cleanup. Visible behavior remains for reviewer verification.

Queue guarantees cover normal execution, handled AI failures, and pre-acceptance dispatch failures. Concurrent-request deduplication, worker crashes/timeouts, and exactly-once delivery are outside this change's proposal.
